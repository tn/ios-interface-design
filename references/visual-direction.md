# Choose a product-specific direction

Read this file for a new interface or substantial changes to the screen composition. Skip this file for a local fix to spacing, color, or a hit area.

## Turn an adjective into a decision

Replace “make it premium” with a statement about visible design decisions:

> A personal reading library should emphasize book identity and reading progress. Use a list with minimal decoration. Provide generous space between the title and author. Use the system serif variant for book titles. Use one chosen accent for actions.
>
> Keep controls familiar. Let book covers provide visual variety.

This design statement applies to the example product. It is not a universal theme. It constrains hierarchy, typography, color, and interaction without prescribing every pixel.

| Product task | Possible composition | Possible visual character | Possible mistake |
| --- | --- | --- | --- |
| Log a strength-training set | Show the current exercise, editable set rows, and a reachable completion control. | Use strong numeric hierarchy, stable columns, and immediate feedback. | Ring charts and streak cards move the active set outside the visible area. |
| Browse a recipe collection | Use recognizable food photography, useful titles, and compact sorting controls. | Use consistent crops, appetizing imagery, and spacing that supports reading. | A large featured banner repeats above every list. |
| Write a private journal entry | Prioritize the writing surface. Provide contextual tools and an unobtrusive date. | Use system type, suitable line lengths, and restrained editing transitions. | Mood chips, quotes, statistics, and illustrations surround the editor. |
| Check spending | Show a meaningful total and period. Provide readable transactions and category details on demand. | Use tabular numerals and clear selection. | Decorative charts, arbitrary percentages, and six unrelated summary tiles compete for attention. |

Use these examples to compare possible design decisions. Do not copy them as presets. Do not add any of these features unless the product needs them.

## Study references before adapting their styling

Use supplied references first. For substantial new work, study released iPhone or iPad interfaces with comparable tasks when browsing is available.

For an explicitly requested style, additional visual references can help explain its defining traits. Label any non-iOS material as visual inspiration. Do not use it to substantiate iOS trends or interaction behavior.

1. Choose iPhone or iPad applications with comparable user tasks.
2. Check app screens on their official sites or App Store listings.
3. Check the device context and the evidence date.

For each reference you check, retain only a relevant lesson:

- **Evidence:** What does the screen or clip show? Identify that screen or clip.
- **Relationship:** What dominates? Which items form a group? How does the user act?
- **Transfer:** Which relationship improves this product's task?
- **Boundary:** Which styling, assets, or interactions should remain specific to the reference?

Do not infer animation from a still image. Do not infer exact color values from prose. If visual evidence is unavailable, state the limitation. In that case, proceed from the brief and native conventions. Reference research must not block a small task.

## Check the direction before implementation

Consider whether changing only the logo and accent would make the screen suitable for any other app. If so, check for missing hierarchy or interactions specific to this product. Also check whether the chosen style changes the relevant geometry, surfaces, and control states. Do not add unrelated decoration to conceal a missing design decision.
